## 一、问题描述

### 现象

主机通过长按电源键 10 秒或 Jetson T5000 系统界面点击“关机”后，ARGB 灯条有时保持绿色常亮。部分情况下会先短暂熄灭，随后又亮回绿色。

### 触发方式

- 长按电源键 10 秒关机；
- Jetson T5000 系统界面点击“关机”。

### 影响

- 灯态与主机状态不一致，用户可感知；
- 不影响主机功能、WOL 和电源状态机。

### 关机时的串口日志

```text
<--mini54-->  soc power off
<--mini54-->  shutdown...
<--mini54-->  STATE: PoweringOff
<--mini54-->  config_wol
<--mini54-->  STATE: PowerOff
```

日志说明 `RGB_HostOff()` 已经被调用，关机检测和黑帧发送都不是问题。灯之后又亮回来，说明灭灯状态被清掉了。

### 定位难点

关机检测日志齐全，黑帧也确实发过，但灯在之后又亮回来。问题不在“检测”或“发送”，而在“状态保持”。

---

## 二、问题原因

### 主因：关机后状态脚回跳，运行期轮询清锁存

复亮链路：

1. 关机时 `PWR_STATUS0/1`（P3.2 / P5.4）为 `POWER_OFF (1,1)`，`RGB_HostOff()` 置锁存并立即发送黑帧。
2. `PoweringOff()` 拉低 `PMIC_EN0`，`config_wol()` 翻转 `HOST_WOL_EN` 并初始化 PHY。
3. PHY / 模块电源上下电之后，状态脚从 `POWER_OFF` 回跳到类似 `POWER_ON (0,0)` 的电平。
4. 旧版 `led_host_is_off()` 在运行期轮询里用 `POWER_ON` 清除 `led_host_off`（单次采样，或连续 50 tick / 500ms 去抖）。
5. `RGB_Process()` 恢复走 `LED_MODE_ON`，绿灯重新发出并锁存。

**关键结论**：真正需要保证的不是“发一帧黑”，而是“黑之后不会被任何状态脚轮询清掉”。状态脚是模块的输出、MCU 的输入，代码并没有写它；WOL 只是通过 PHY / 电源时序间接影响它。最终版因此不再用状态脚清锁存。

### 次要原因：上电请求阶段清锁存

旧版还在 `PowerOnhostBoard()` 和 `PoweringOn()` 的 INIT 阶段清除锁存。这两个位置是“上电请求”，不是“主机已经起来”。关机后按键抖动、WOL PME、RTC 等唤醒请求都可能提前清掉锁存，导致灯在主机没有真正上电时又亮起来。

### WOL 配置的影响

- **WOL 开启**：S5 保持，灯条和 `VCC_3V3_S0` 都一直有电，灯灭不灭完全由 MCU 的锁存决定。`config_wol()` 会阻塞 3.2 秒，黑帧必须在它之前同步发出。
- **WOL 关闭**：`PoweringOff()` 拉低 `HOST_POWER_ENABLE`，S5 连同灯条供电一起断开，灯自己就灭，不需要发黑帧。
- **WOL 唤醒**：锁存保持到 `PoweringOn()` 确认 `PWR_GOOD=1 && status=POWER_ON` 才清除，避免一个唤醒请求就把灯提前点亮。

### 已排除的方向

- **不是关机检测失败**：日志里 `soc power off`、`shutdown...`、`STATE: PoweringOff` 都出现了。
- **不是驱动器掉电**：Thor 的 `VCC_3V3_S0` 由载板 U31（SY8286ARAC）从 `12V_S5` 生成，经 FB15 接模块 `VSUS33`；WOL 开启时 S5 保持，这条轨一直有电，黑帧可以锁存。
- **不是刷新策略**：之前“变化才发”导致灯带不跟随，是另一个独立问题，与关机复亮无关。

### 历史版本为什么没解决

| 版本 | 清除锁存的方式 | 失败原因 |
|---|---|---|
| `power_off_state` 版 | 进入 `PowerOff` 后按标志发黑 | 太晚：`PMIC_EN0=0` 之后才发，黑帧赶不上电源变化；标志初值/上电语义也不合适。 |
| 单次采样版 | 任意一次 `POWER_ON` 即清 | 状态脚在 `config_wol()` 后回跳一次就清掉，表现为“偶尔”复亮。 |
| 50 tick / 1 秒去抖版 | 连续 200–500ms 是 `POWER_ON` 才清 | 只是把复亮推迟了 0.5–1 秒；状态脚回跳后一直保持 `POWER_ON`，时间一到仍然清。 |
| 上电请求清除版 | `PowerOnhostBoard()` / `PoweringOn INIT` 清 | 关机后的按键抖动或唤醒请求会提前清锁存，主机没有真正上电灯也会亮。 |
| “变化才发”版 | 与锁存无关 | 灯带不跟随颜色/模式变化，属于刷新策略问题，不应与关机复亮混在一起。 |

## 三、问题解决

### 设计原则

把灭灯做成单向锁存：关机时置位，运行期只补黑、不清除；只有一次确认成功的上电才允许恢复显示。

### 核心实现

```c
static volatile uint8_t led_host_off = 1;

void RGB_HostOff(void)
{
    led_host_off = 1;
    led_ctrl.led_on = 0;
    RGB_SendData(led_ctrl.colors.color_off);   /* 立即发，不等下一个 tick */
}

void RGB_HostOn(void)
{
    led_host_off = 0;
}
```

`RGB_Process()` 在锁存期间每 10ms 补一帧黑帧并直接返回；`RGB_SendData()` 在关中断临界区内再查一次锁存，防止主循环准备好的绿帧覆盖黑帧。`led_host_is_off()` 现在只做一件事：状态脚为 `POWER_OFF` 就置 1，永远不清。

### 清除条件

```c
if ((PWR_GOOD == 1) && (get_host_power_status() == POWER_ON))
{
    RGB_HostOn();
    enter_power_state(PowerOn);
}
```

这是唯一的运行期清除点，位于 `PoweringOn()` 确认主机真正起来之后。启动时 `init_led_colors()` 另做一次判断：只有 `PWR_GOOD=1 && status=POWER_ON && FORCE_OFF=1` 才允许亮，避免 MCU 在主机已关机时复位误亮。

### 改动清单

| 文件 | 改动 |
|---|---|
| `function/src/led.c` | 单向锁存；`RGB_HostOff/HostOn`；锁存期间补黑；发送前复查；启动初值。 |
| `function/inc/led.h` | 新增两个函数声明。 |
| `function/src/pm.c` | `is_host_poweroff()` 分支、`config_wol()` 之前调 `RGB_HostOff()`。 |
| `function/src/power_control.c` | `PoweringOff()` 里、`PMIC_EN0=0` 之前打黑；`PoweringOn()` 确认上电后才 `RGB_HostOn()`。 |

### 验证结果

- 主机侧单元测试 4 组全部通过，包括“关机后状态脚回跳 `POWER_ON`，1000 tick 仍保持黑”。
- 实机：长按电源键 10 秒关机 5 次，灯态正常。
- 实机：Jetson T5000 系统界面关机 5 次，灯态正常。
